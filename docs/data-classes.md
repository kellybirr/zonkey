# Data Classes & Attributes

This document is a detailed reference for defining data classes in Zonkey -- the C# classes that map to database tables.

## Overview

Zonkey maps C# classes to database tables using attributes. There are three levels of opt-in, and you choose the level that fits your use case:

1. **Attributes only on a plain class** -- works for read-only queries (`Fill`, `GetOne`). The adapter can populate the object's properties from a data reader, but there is no change tracking. You cannot call `Save` on these objects.

2. **Attributes + `DataClass` base class** -- adds change tracking via `SetFieldValue`. Every property change is recorded, and `DataRowState` transitions automatically. This is required for `Save` operations (INSERT and UPDATE).

3. **Attributes + `DataClass` + lifecycle hooks** -- full lifecycle support with `OnBeforeSave` and `OnAfterSave` virtual methods. Override these to inject validation, set audit fields, or perform post-save processing.

This layered approach means you only add what you need. A simple reporting query can use a plain class with attributes, while a fully tracked entity uses `DataClass` with lifecycle hooks.

## DataItemAttribute

`DataItemAttribute` is a class-level attribute that maps a C# class to a database table. It lives in the `Zonkey.ObjectModel` namespace.

```csharp
[DataItem("products", SchemaName = "store")]
public class Product : DataClass { ... }
```

### Properties

| Property | Type | Default | Description |
|---|---|---|---|
| `TableName` | `string` | *(required)* | The database table name. Passed as the constructor argument. |
| `SchemaName` | `string` | `null` | Database schema (e.g., `"dbo"`, `"public"`, `"store"`). |
| `SaveToTable` | `string` | same as `TableName` | Alternative table name for save operations. Useful when reading from a view but writing to the underlying table. |
| `AccessType` | `AccessType` | `ReadWrite` | Declarative only at the class level -- the adapter does not currently enforce it. Read-only protection comes from not implementing `ISavable`; per-field `AccessType` *is* enforced. |
| `UpdateCriteria` | `UpdateCriteria` | `Default` | How the WHERE clause is built for UPDATE statements: `Default`, `KeyOnly`, `KeyAndVersion`, `ChangedFields`, or `AllFields`. |
| `SelectBack` | `SelectBack` | `Default` | What to SELECT back after an INSERT or UPDATE: `Default`, `None`, `IdentityOrVersion`, `UnchangedFields`, or `AllFields`. |
| `UseQuotedIdentifier` | `bool?` | `null` | Force quoted identifiers (e.g., `[column]` in SQL Server, `"column"` in PostgreSQL). When `null`, uses the adapter's default. **Cannot be set in attribute syntax** -- `bool?` is not a legal attribute argument (CS0655); set it by mutating a generated `DataMap` at runtime, or use the adapter-level `SetProperty(AdapterProperty.UseQuotedIdentifiers, ...)`. |
| `ImplicitFieldDefinition` | `bool` | `false` | When `true`, auto-generates field mappings from property names without requiring `DataFieldAttribute` on every property. |
| `IncludePrivateProperties` | `bool` | `false` | When `true`, private properties are included in the data map alongside public ones. |

## DataFieldAttribute

`DataFieldAttribute` is a property-level attribute that maps a C# property to a database column. It lives in the `Zonkey.ObjectModel` namespace.

```csharp
[DataField("product_name", DbType.String, false, Length = 200)]
public string Name { get => _name; set => SetFieldValue(ref _name, value); }
```

### Constructor Parameters

| Parameter | Type | Description |
|---|---|---|
| `fieldName` | `string` | The database column name. |
| `dataType` | `DbType` | The database type (`DbType.Int32`, `DbType.String`, `DbType.Decimal`, `DbType.DateTime`, `DbType.Binary`, etc.). |
| `isNullable` | `bool` *(optional)* | Whether NULL is allowed. Defaults to `false` if omitted -- pass `true` explicitly for nullable columns. |

### Additional Properties

| Property | Type | Default | Description |
|---|---|---|---|
| `IsKeyField` | `bool` | `false` | Marks the column as a primary key. Used in WHERE clauses for UPDATE and DELETE. |
| `IsAutoIncrement` | `bool` | `false` | Marks the column as an identity/auto-increment column. The value is generated by the database on INSERT. |
| `IsRowVersion` | `bool` | `false` | Marks the column as a row version/timestamp for optimistic concurrency. |
| `IsNullable` | `bool` | `false` | Whether the column allows NULL values. |
| `IsComparable` | `bool` | *(auto)* | Whether the field can be used with `=` in a WHERE clause for concurrency checks. Defaults to `true` for most types, `false` for XML and long fields. |
| `IsPartitionKey` | `bool` | `false` | Includes the field in WHERE clauses for UPDATE and SelectBack operations. Useful for partitioned databases to improve query performance. Has no effect on fields already marked `IsKeyField`. |
| `Length` | `int` | `-1` | Field length. Important for string columns to ensure correct parameter sizing. |
| `AccessType` | `AccessType` | `ReadWrite` | Controls whether the field is `ReadOnly`, `WriteOnly`, or `ReadWrite`. |
| `DateTimeKind` | `DateTimeKind` | `Unspecified` | Applied when reading `DateTime` values from the database. Set to `Utc` for UTC timestamps, `Local` for local times. |
| `SequenceName` | `string` | `null` | Database sequence name for auto-increment columns (PostgreSQL, Oracle). |
| `TrimToFit` | `bool` | `false` | When `true`, automatically trims strings that exceed `Length` instead of raising an error. |
| `UseQuotedIdentifier` | `bool?` | `null` | Force (or suppress) quoted identifiers for this specific column. **Cannot be set in attribute syntax** (`bool?` is not a legal attribute argument); set it on a generated `DataMap` at runtime. See `docs/todo-dataclass-virtual-computed-columns.md`. |
| `SchemaVersion` | `int` | `0` | Schema version for the field. Used with `DataClassAdapter` schema version filtering to support evolving database schemas across deployments. An adapter schema version of `0` means "no filtering" (all fields included); otherwise fields with `SchemaVersion` less than or equal to the adapter's version are included. |

## DataClass Base Class

`DataClass` is the abstract base class that provides change tracking. It lives in the `Zonkey.ObjectModel` namespace and implements `ISavable`.

### Constructor

```csharp
protected DataClass(bool addingNew)
```

If `addingNew` is `true`, sets `DataRowState` to `Added`. If `false`, sets it to `Detached`.

Your subclass also needs a **public parameterless constructor** (conventionally `public MyClass() : base(false)`): the adapter materializes query results through generated IL that requires it, and throws `InvalidOperationException` if it is missing. The alternative is supplying a custom `adapter.ObjectFactory` delegate.

### Key Members

**`DataRowState DataRowState { get; set; }`**
Tracks the object's current state. Uses the `System.Data.DataRowState` enum.

**`IDictionary<string, object> OriginalValues { get; }`**
Stores pre-modification values keyed by property name. Populated automatically by `SetFieldValue` when a property is changed for the first time.

**`void CommitValues()`**
Clears `OriginalValues` and sets `DataRowState` to `Unchanged`. Called automatically by the adapter after a successful save. You rarely need to call this directly.

**`protected void SetFieldValue<T>(ref T fieldRef, T value, [CallerMemberName] string fieldName = "")`**
Updates the backing field and tracks the change. On the first change to a property (when the state is `Unchanged` or `Modified`), it captures the original value in `OriginalValues`. If the state is `Unchanged`, it transitions to `Modified`.

Two behaviors worth knowing:

- **There is no equality check.** Assigning a property its current value still snapshots the original and flips an `Unchanged` object to `Modified` -- a no-op assignment triggers a real UPDATE on the next save. This is a deliberate simplicity/performance trade-off (no boxing or `Equals` call per setter); guard the assignment yourself if it matters.
- **Nothing is tracked in the `Added` or `Detached` states.** `OriginalValues` stays empty for new objects; original-value tracking begins only after the object reaches `Unchanged` (i.e., after materialization or a save).

**`protected internal virtual void OnBeforeSave()`**
Called by the adapter at the start of every `Save` call -- including saves that are then skipped because the object is `Unchanged`. Override this to perform validation, set audit fields, or apply default values.

**`protected internal virtual void OnAfterSave(bool isNewRow)`**
Called by the adapter after a successful save. Override this for post-save processing such as cache invalidation or event publishing. Note: as of v6.6 the adapter passes `isNewRow: true` for both inserts and updates -- do not rely on it to distinguish the operation; check `DataRowState` in `OnBeforeSave` instead if you need to know.

### DataRowState Flow

```
new MyClass(addingNew: true)  --> Added
new MyClass(addingNew: false) --> Detached
adapter.Fill(...)             --> Unchanged  (CommitValues called by adapter)
adapter.GetOne(...)           --> Unchanged  (CommitValues called by adapter)
obj.SomeProperty = value      --> Modified   (via SetFieldValue, from Unchanged)
adapter.Save(obj) [insert]    --> Unchanged  (CommitValues called after save)
adapter.Save(obj) [update]    --> Unchanged  (CommitValues called after save)
```

`DataRowState` drives save behavior:

- **Added** -- the adapter performs an INSERT.
- **Modified** -- the adapter performs an UPDATE, targeting only the changed columns.
- **Unchanged** -- the adapter skips the object (no database operation).
- **Detached** -- the adapter throws an `InvalidOperationException`. This state indicates the object was not constructed for saving. If you see this error, you likely used the parameterless constructor when you should have used `new MyClass(addingNew: true)`.

## ISavable Interface

`ISavable` is the interface that `DataClass` implements. The `DataClassAdapter` checks for `ISavable` at runtime to determine whether an object supports save operations.

```csharp
public interface ISavable
{
    void CommitValues();
    DataRowState DataRowState { get; set; }
    IDictionary<string, object> OriginalValues { get; }
}
```

You can implement `ISavable` directly if you do not want to inherit from `DataClass`. This is useful when your class already has a base class and multiple inheritance is not available. As long as your class implements `ISavable`, the adapter can perform INSERT and UPDATE operations on it. You are responsible for implementing change tracking in your `SetFieldValue` equivalent and maintaining `OriginalValues` correctly.

One caveat: the `OnBeforeSave`/`OnAfterSave` lifecycle hooks are `DataClass` virtuals, not `ISavable` members -- the adapter casts to `DataClass` to invoke them, so they never fire for a hand-rolled `ISavable` implementation.

## IKeyed and IKeyed&lt;TKey&gt; Interfaces

These optional interfaces provide typed key access for data classes:

```csharp
public interface IKeyed
{
    object GetKey();
}

public interface IKeyed<out TKey>
{
    TKey GetKey();
}
```

The `DataClass<TKey>` generic subclass implements both interfaces automatically. It uses reflection to find the property marked with `IsKeyField = true` and builds a fast delegate to return the key value:

```csharp
[DataItem("products")]
public class Product : DataClass<int>
{
    private int _id;

    public Product() : base(false) { }
    public Product(bool addingNew) : base(addingNew) { }

    [DataField("id", DbType.Int32, IsKeyField = true, IsAutoIncrement = true)]
    public int Id { get => _id; set => SetFieldValue(ref _id, value); }

    // other properties...
}

// Usage
var product = await adapter.GetOne(p => p.Id == 42);
int key = product.GetKey(); // returns 42
```

For composite keys, `DataClass<TKey>` supports value tuples as the type parameter (e.g., `DataClass<(int, int)>`). Key properties are paired to tuple positions by **property declaration order**, not by name -- keep the declaration order of your key properties in sync with the tuple.

## Read-Only Data Classes

For queries that only need to read data, you can define a class without inheriting from `DataClass`. This is lighter weight and appropriate for projections, summaries, or reporting views.

```csharp
[DataItem("products")]
public class ProductSummary
{
    [DataField("id", DbType.Int32, IsKeyField = true)]
    public int Id { get; set; }

    [DataField("name", DbType.String)]
    public string Name { get; set; } = "";

    [DataField("price", DbType.Decimal)]
    public decimal Price { get; set; }
}
```

This class works with `Fill` and `GetOne`:

```csharp
var summaries = new List<ProductSummary>();
await adapter.Fill(summaries, p => p.Price < 50.00m);
```

However, it cannot be saved. Calling `Save` on an object that does not implement `ISavable` throws an `ArgumentException` -- that absence is what makes the class read-only. (The class-level `AccessType` property is not enforced, so there is no need to set it.) There is no change tracking because there is no `SetFieldValue` call in the property setters.

## Implicit Field Definition

When `ImplicitFieldDefinition = true` on `DataItemAttribute`, Zonkey auto-generates field mappings from property names. You do not need `DataFieldAttribute` on every property.

```csharp
[DataItem("products", ImplicitFieldDefinition = true)]
public class Product : DataClass
{
    public Product() : base(false) { }
    public int Id { get; set; }
    public string Name { get; set; } = "";
}
```

Zonkey infers the `DbType` from the property's CLR type and uses the property name as the column name. Some conventions are applied automatically:

- Properties named `RowVersion` (case-insensitive) with type `byte[]` are treated as row version fields.
- `DateTime` properties whose names end in `UTC` (case-insensitive) have `DateTimeKind.Utc` applied.

Key fields still need explicit `DataFieldAttribute` attributes to mark them as `IsKeyField = true`, or you can supply the key field names through the `DataClassAdapter` constructor. Without a key field identified, UPDATE and DELETE operations will fail.

## Complete Example

Here is a realistic `Order` class demonstrating multiple field types, a row version for concurrency, and a lifecycle hook:

```csharp
[DataItem("orders", SchemaName = "store")]
public class Order : DataClass
{
    private int _id;
    private int _customerId;
    private DateTime _orderDate;
    private string _status = "pending";
    private decimal _total;
    private DateTime? _modifiedUtc;
    private byte[] _rowVersion = [];

    public Order() : base(false) { }
    public Order(bool addingNew) : base(addingNew)
    {
        if (addingNew)
            _orderDate = DateTime.UtcNow;
    }

    [DataField("id", DbType.Int32, IsKeyField = true, IsAutoIncrement = true)]
    public int Id { get => _id; set => SetFieldValue(ref _id, value); }

    [DataField("customer_id", DbType.Int32, false)]
    public int CustomerId { get => _customerId; set => SetFieldValue(ref _customerId, value); }

    [DataField("order_date", DbType.DateTime, false, DateTimeKind = DateTimeKind.Utc)]
    public DateTime OrderDate { get => _orderDate; set => SetFieldValue(ref _orderDate, value); }

    [DataField("status", DbType.String, false, Length = 20)]
    public string Status { get => _status; set => SetFieldValue(ref _status, value); }

    [DataField("total", DbType.Decimal, false)]
    public decimal Total { get => _total; set => SetFieldValue(ref _total, value); }

    [DataField("modified_utc", DbType.DateTime, DateTimeKind = DateTimeKind.Utc)]
    public DateTime? ModifiedUtc { get => _modifiedUtc; set => SetFieldValue(ref _modifiedUtc, value); }

    [DataField("row_version", DbType.Binary, false, IsRowVersion = true)]
    public byte[] RowVersion { get => _rowVersion; set => SetFieldValue(ref _rowVersion, value); }

    protected override void OnBeforeSave()
    {
        if (DataRowState == DataRowState.Added && _customerId == default)
            throw new InvalidOperationException("Cannot insert an Order without a CustomerId. Set CustomerId before calling Save.");

        _modifiedUtc = DateTime.UtcNow;
    }
}
```

Key points in this example:

- **`SchemaName = "store"`** qualifies the table as `store.orders` in the generated SQL.
- **`IsAutoIncrement = true`** on `Id` tells the adapter to omit this column from INSERT statements and select back the generated value.
- **`IsRowVersion = true`** on `RowVersion` enables optimistic concurrency. When `UpdateCriteria` is `KeyAndVersion`, the adapter includes the row version in the UPDATE WHERE clause.
- **`DateTimeKind = DateTimeKind.Utc`** on `OrderDate` ensures that `DateTime` values read from the database have `Kind` set to `Utc`.
- **`OrderDate` is initialized in the constructor** when `addingNew` is `true`, so new orders get a creation timestamp immediately at construction time rather than at save time.
- **`OnBeforeSave`** does two things: validates that new orders have a `CustomerId` set (throwing early with a clear message instead of letting the database reject a foreign key violation), and sets `ModifiedUtc` on every save for audit tracking.

## Using the `field` Keyword (.NET 10+)

Starting with C# 14 / .NET 10, the `field` keyword gives you access to the compiler-generated backing field inside a property accessor. This eliminates the need to declare explicit backing fields while still using `SetFieldValue` for change tracking.

Instead of the traditional pattern:

```csharp
private int _id;
private string _name = "";
private decimal _price;

[DataField("id", DbType.Int32, IsKeyField = true, IsAutoIncrement = true)]
public int Id { get => _id; set => SetFieldValue(ref _id, value); }

[DataField("name", DbType.String, false, Length = 100)]
public string Name { get => _name; set => SetFieldValue(ref _name, value); }

[DataField("price", DbType.Decimal, false)]
public decimal Price { get => _price; set => SetFieldValue(ref _price, value); }
```

You can write:

```csharp
[DataField("id", DbType.Int32, IsKeyField = true, IsAutoIncrement = true)]
public int Id { get => field; set => SetFieldValue(ref field, value); }

[DataField("name", DbType.String, false, Length = 100)]
public string Name { get => field; set => SetFieldValue(ref field, value); } = "";

[DataField("price", DbType.Decimal, false)]
public decimal Price { get => field; set => SetFieldValue(ref field, value); }
```

The `field` keyword refers to the auto-generated backing field, so `ref field` works with `SetFieldValue` exactly like `ref _name` did. Property initializers (e.g., `= ""`) set the backing field's default value.

Here is the complete `Order` example rewritten with `field`:

```csharp
[DataItem("orders", SchemaName = "store")]
public class Order : DataClass
{
    public Order() : base(false) { }
    public Order(bool addingNew) : base(addingNew)
    {
        if (addingNew)
            OrderDate = DateTime.UtcNow;
    }

    [DataField("id", DbType.Int32, IsKeyField = true, IsAutoIncrement = true)]
    public int Id { get => field; set => SetFieldValue(ref field, value); }

    [DataField("customer_id", DbType.Int32, false)]
    public int CustomerId { get => field; set => SetFieldValue(ref field, value); }

    [DataField("order_date", DbType.DateTime, false, DateTimeKind = DateTimeKind.Utc)]
    public DateTime OrderDate { get => field; set => SetFieldValue(ref field, value); }

    [DataField("status", DbType.String, false, Length = 20)]
    public string Status { get => field; set => SetFieldValue(ref field, value); } = "pending";

    [DataField("total", DbType.Decimal, false)]
    public decimal Total { get => field; set => SetFieldValue(ref field, value); }

    [DataField("modified_utc", DbType.DateTime, DateTimeKind = DateTimeKind.Utc)]
    public DateTime? ModifiedUtc { get => field; set => SetFieldValue(ref field, value); }

    [DataField("row_version", DbType.Binary, false, IsRowVersion = true)]
    public byte[] RowVersion { get => field; set => SetFieldValue(ref field, value); } = [];

    protected override void OnBeforeSave()
    {
        if (DataRowState == DataRowState.Added && CustomerId == default)
            throw new InvalidOperationException("Cannot insert an Order without a CustomerId. Set CustomerId before calling Save.");

        ModifiedUtc = DateTime.UtcNow;
    }
}
```

Both patterns -- explicit backing fields and the `field` keyword -- are fully supported. Use whichever your team prefers or whichever your target framework allows.

## DataMap (Advanced)

`DataMap` is the internal reflection cache that Zonkey uses to map between objects and database columns. When you create a `DataClassAdapter`, it calls `DataMap.GenerateCached` to build (or retrieve from cache) a `DataMap` for your class type. The map is built from the `DataItemAttribute` and `DataFieldAttribute` values on your class.

A design detail that makes runtime customization possible: the attributes **are** the map. `DataFieldAttribute` implements `IDataMapField`, and `DataMap` stores the attribute instances themselves rather than copying their values into separate field objects. Because reflection materializes a *fresh* attribute instance on every `GetCustomAttribute` call, each generated map owns its own instances -- which is why mutating a `GenerateNew` map is safe and isolated, while mutating a `GenerateCached` map affects **every adapter for that type, process-wide**. Only mutate maps you created with `GenerateNew` (or accept the global consequences deliberately).

In normal usage, you never interact with `DataMap` directly. However, advanced scenarios may require programmatic control:

- **`DataMap.GenerateCached(Type type)`** -- generates a `DataMap` and caches it for reuse. Subsequent calls with the same type return the cached instance.
- **`DataMap.GenerateCached(Type type, string tableName, string[] keyFields)`** -- generates a cached map with a custom table name and/or key field overrides. This is useful when one class maps to multiple tables.
- **`DataMap.GenerateCached(Type type, string tableName, string[] keyFields, int schemaVersion)`** -- adds schema version filtering. Only fields with `SchemaVersion` less than or equal to the specified version are included.
- **`DataMap.GenerateNew(Type type)`** -- generates a new `DataMap` without caching. Use this when you need a one-off map that you will modify programmatically.

You can pass a custom `DataMap` to the `DataClassAdapter` constructor:

```csharp
var map = DataMap.GenerateNew(typeof(Product));
map.DataItem.TableName = "products_archive";

var adapter = new DataClassAdapter<Product>(connection, map);
```

This is also how you can add, remove, or modify field mappings at runtime using the `AddField`, `AddKeyField`, `AddRowVersionField`, and `RemoveField` methods on `DataMap`.
